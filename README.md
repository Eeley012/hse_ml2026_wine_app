# 🍷 Подбор хороших вин — демо-приложение

Streamlit-приложение к ДЗ-3: показывает, как логистическая регрессия отбирает
«хорошие» вина (оценка эксперта не ниже 7) по результатам лабораторного анализа.

## Как запустить

Python 3.13.9 (проверено на нём; подойдёт любой 3.10+).

```bash
cd wine_app
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Приложение откроется на http://localhost:8501.

## Содержимое папки

| файл | что это |
|---|---|
| `app.py` | само приложение |
| `model.joblib` | пайплайн `StandardScaler + LogisticRegression`, обученный на тренировочной выборке |
| `config.json` | порог, выбранный по валидации в задании 2.5 |
| `test.csv` | тестовая выборка с колонкой `target` для вкладки с метриками |
| `requirements.txt` | версии библиотек, на которых приложение запускается |

## Вкладки

- **Оценка вина** — ввод 12 признаков, вероятность и решение модели при текущем пороге.
- **Модельные метрики** — матрица ошибок, precision / recall / F1, ROC- и PR-кривые
  с отмеченной текущей рабочей точкой. Всё пересчитывается при движении слайдера порога.
- **Пакетное предсказание** — загрузка CSV с признаками вин, таблица с вероятностями
  и решениями, выгрузка результата.
- **Что выучила модель** — коэффициенты логистической регрессии после масштабирования.

Порог задаётся один раз в сайдбаре и действует на всех вкладках.

## Про кэширование (задание 4.5)

- **Модель — `st.cache_resource`.** Это один тяжёлый объект на весь сервер: декоратор
  отдаёт всем сессиям ссылку на один и тот же объект, ничего не копируя и не сериализуя.
- **Таблицы — `st.cache_data`.** Такие значения возвращаются копией на каждый вызов,
  поэтому одна сессия не испортит общий кэш, изменив свой `DataFrame`. Для модели это
  не подошло бы: `cache_data` пытается сериализовать результат, и на каждый вызов мы
  получали бы новую копию модели.
- **Без декоратора** `joblib.load` выполнялся бы заново при каждом действии пользователя:
  streamlit перезапускает скрипт сверху вниз на любой клик, так что каждое движение
  слайдера читало бы модель с диска и заново считало `predict_proba` на всей тестовой
  выборке — хотя от порога вероятности не зависят, от него зависит только сравнение с ними.
